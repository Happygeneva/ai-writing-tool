# 🖋️ Streamlitで作る「AIライティングツール」のトップページを読み解く

`app.py` は、このアプリを起動したときに一番最初に表示される「ホーム画面」を作っているファイルです。全体でわずか32行ですが、Streamlitの基本的な使い方がぎゅっと詰まっています。上から順に見ていきましょう。

---

## 1. ページの初期設定

```python
import streamlit as st

st.set_page_config(page_title="AIライティングツール", page_icon="🖋️", layout="wide")
```

`streamlit` は、Pythonだけでブラウザ上のWebアプリを作れるライブラリです。`st.set_page_config()` はその中でも一番最初に呼ぶべき「ページ全体の設定」で、以下を指定しています。

- `page_title` … ブラウザのタブに表示されるタイトル
- `page_icon` … タブのファビコン（絵文字をそのまま使えるのがStreamlitらしいところ）
- `layout="wide"` … 画面幅いっぱいにコンテンツを表示するモード（デフォルトは中央寄せの狭いレイアウト）

---

## 2. 見出し部分

```python
st.title("🖋️ AIライティングツール")
st.caption("Gemini を使った個人用のライティング支援ツール集です。左のメニューから使いたい機能を選んでください。")
st.divider()
```

ここは見たまま、上から「大きな見出し（`st.title`）」「小さな説明文（`st.caption`）」「区切り線（`st.divider`）」を並べているだけです。Streamlitは `st.〇〇()` を呼ぶ順番がそのまま画面の表示順になる、という素直な仕組みになっています。

---

## 3. 機能一覧をデータとして持つ

```python
features = [
    ("pages/1_📝_ブログ記事作成.py", "📝 ブログ記事作成", "テーマとキーワードからブログ記事の下書きを生成します。"),
    ("pages/2_✉️_メール返信.py", "✉️ メール返信作成", "受信メールの内容から返信文の下書きを作成します。"),
    ...
]
```

ここがこのファイルの肝です。8つの機能ページへの情報を、**「(ファイルパス, 表示ラベル, 説明文)」というタプルのリスト**として1箇所にまとめています。

こうしておくメリットは、「機能カードを画面にどう並べるか」というロジック（次で説明します）と、「どんな機能があるか」というデータを分離できることです。新しい機能を追加したいときは、このリストに1行足すだけで済みます。

---

## 4. カード状に2列で並べる

```python
cols = st.columns(2)
for i, (path, label, desc) in enumerate(features):
    with cols[i % 2]:
        with st.container(border=True):
            st.page_link(path, label=label)
            st.write(desc)
```

少し凝った部分なので、分解してみます。

- **`st.columns(2)`**：画面を左右2列に分割し、`cols[0]`（左）と`cols[1]`（右）という2つの「入れ物」を作ります。
- **`i % 2`（剰余演算）**：`features` を`enumerate`でインデックス`i`付きループしながら、`i`が偶数なら左列（`cols[0]`）、奇数なら右列（`cols[1]`）に交互に振り分けています。これにより8個の機能が2列×4行のグリッド状に並びます。
- **`with cols[i % 2]:`**：「これ以降に書く内容は、この列の中に配置してね」という意味の`with`構文です。Streamlitでは、コンテナ系の要素（列・タブ・囲み枠など）は`with`で使うのが定番パターンです。
- **`with st.container(border=True):`**：さらにその中に、枠線付きの「カード」を作っています。ネストした`with`によって「列の中にカードがある」という入れ子構造を表現しています。
- **`st.page_link(path, label=label)`**：カードの中に、他のページ（`pages/`フォルダ内のファイル）へ飛べるリンクを置いています。Streamlitのマルチページ機能では、`pages/`配下の各`.py`ファイルが自動的に個別ページとして扱われるので、`app.py`からはファイルパスを指定するだけでナビゲーションが作れます。
- **`st.write(desc)`**：カード内にリンクの下に説明文を表示。

つまりこのループ全体で「機能データのリスト → 2列のカードグリッドUI」への変換をやっているわけです。

---

## 5. 最後に案内メッセージ

```python
st.divider()
st.info(
    "初回利用時は、プロジェクト直下に `.env` ファイルを作成し "
    "`GEMINI_API_KEY=あなたのAPIキー` を設定してください（`.env.example` を参考にしてください）。"
)
```

再度区切り線を挟んで、`st.info()` で青い情報ボックスを表示しています。この文言は、実際にアプリを使う前提として「Gemini APIキーを`.env`に設定する必要がある」ことを利用者に伝えるものです（この設定は`core/config.py`が読み込み、キーが無ければ各機能ページでエラー表示される仕組みになっています）。

---

## まとめ：このファイルの役割

`app.py`がやっていることは実はシンプルで、

1. ページの見た目の基本設定をする
2. 見出しと説明を表示する
3. **8つの機能ページへのリンク集を、データ駆動でカードUIとして描画する**
4. 初期設定の案内を出す

だけです。実際の「AIで文章を生成する」処理は一切書かれておらず、それは`pages/`配下の各ファイルと`core/gemini_client.py`が担当しています。`app.py`はあくまで「入口・目次」の役割に徹している、という設計になっています。
